# 知识库配置与启动清单（从零跑起来）

本清单覆盖 `kb/` monorepo 中两个模块的**配置与启动分步操作**。代码说明见仓库根 [`README.md`](../README.md)。

---

## 0. 前置条件
- Python 3.10+（本机 3.8.9 可跑但兼容性边缘，建议 3.10+）
- 已安装 Git
- 能访问外网（通义百炼 / 各模型厂商 API）

---

## 1. 获取 API Key（最关键的一步）

知识库问答依赖**通义百炼**的 `qwen`（对话）与 `text-embedding-v3`（向量化）：

1. 打开 [阿里云百炼控制台](https://dashscope.console.aliyun.com/)
2. 右上角 **API-KEY** → **创建 API Key**，复制 `sk-...`
3. 进入「模型广场」，确认已开通 `qwen-turbo` 与 `text-embedding-v3`（需账户有额度）
4. 将 Key 填入 `kb/.env` 的 `DASHSCOPE_API_KEY`

> 若还要用 ai_service 接入其他厂商（混元 / 豆包 / DeepSeek / OpenAI / Claude），
> 各自的控制台与 Key 获取地址见 [`README.md`](../README.md) 的「五、相关信息获取地址」表。

## 2. 准备环境

```bash
cd kb

# 虚拟环境
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

# 安装依赖（二选一）
# 方式 A：一次性装全部（最简单，只跑服务用这个即可）
pip install -r requirements.txt
# 方式 B：按包可编辑安装（更规范，并生成 kb-server / ai-service 命令入口）
#   必须在“已激活的虚拟环境”里执行，否则会装到系统 Python、命令不在 PATH。
pip install -e ./kb -e ./ai_service

# 配置密钥：复制模板后编辑
cp .env.example .env              # Windows 用 copy .env.example .env
```

编辑 `.env`，至少填好：
```
DASHSCOPE_API_KEY=sk-你的真实key
KB_PORT=8002
AI_SERVICE_PORT=8000
# 其余按需：ARK_API_KEY / HUNYUAN_API_KEY / DEEPSEEK_API_KEY / OPENAI_API_KEY / ANTHROPIC_API_KEY
```

---

## 3. 启动两个服务（各开一个独立窗口）

```bash
# 窗口 1：知识库 RAG 服务
uvicorn kb.main:app --host 0.0.0.0 --port 8002 --reload

# 窗口 2：多模型接入网关
uvicorn ai_service.main:app --host 0.0.0.0 --port 8000 --reload
```

> 若用「方式 B」按包安装过，可直接用命令入口启动（等价于上面的 uvicorn，端口读 .env）：
> ```bash
> kb-server        # 知识库服务，端口读 KB_PORT
> ai-service       # 多模型网关，端口读 AI_SERVICE_PORT
> ```

## 5. 联调（经 Java 代理）

前端 Vue（:5173）通过 Vite 代理把 `/api/kb/*` 转发到 Java `aicontent`（:8080），
Java 校验 JWT 后内部转发到 `http://localhost:8002/kb/*`（知识库）与 `http://localhost:8000`（网关）。
Python 侧不解析 JWT、不直连公网，安全边界由 Java 侧负责。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 启动报 `DASHSCOPE_API_KEY` 相关错误 | `.env` 未填或路径不对（`kb/config.py` 读同目录 `.env`） |
| 上传文档 `chunkCount=0` | 扫描版 PDF / 图片无文本层，换含可检索文本的文件 |
| 网关调用某厂商鉴权失败 | 对应环境变量（如 `ARK_API_KEY`）未填 |
| 端口被占用（如 8002，WinError 10013） | 见下方「7. 端口被占用排查」 |
| `kb-server` / `ai-service` 命令找不到 | 多半是未激活 venv 就 `pip install`，命令装到了系统 Python 且不在 PATH。先激活 venv，再 `pip install -e ./kb -e ./ai_service`，用 `where kb-server`（Win）/ `which kb-server` 确认落在 `<venv>/Scripts` 或 `<venv>/bin` |

## 7. 端口被占用（WinError 10013）排查

启动报 `ERROR: [Errno 13] ... bind on address ... WinError 10013`，说明目标端口已被占用。按以下顺序排查：

1. **先确认是不是自己已经跑起来的实例**
   回想是否在 PyCharm / 某个终端里之前成功启动过该服务却没 Stop。那个旧进程正占用端口。
   → 直接去原启动处点 **Stop / 关闭窗口**，端口立即释放，无需杀进程。

2. **普通占用：用 netstat + taskkill 结束**
   ```bash
   netstat -ano | findstr :8002          # 找到占用端口的 PID
   taskkill /PID <pid> /F                # 结束该进程
   ```

3. **高权限占用（taskkill 报“拒绝访问”）**
   若 `taskkill` 返回「拒绝访问」，且 `tasklist` 也看不到该 PID，说明它是以更高权限
   （如“以管理员身份运行”的 PyCharm / 终端、或系统级进程）启动的旧进程，普通终端杀不掉。
   - 任务管理器：`Ctrl+Shift+Esc` → 详细信息 → 找 **PID 列 = 该 PID** → 右键「结束任务」（任务管理器权限更高，通常能结束）。
   - 或：右键 PowerShell → **以管理员身份运行** → `taskkill /PID <pid> /F`。

4. **临时绕行（不改代码，只改配置）**
   若以上都搞不定，把 `.env` 的 `KB_PORT`（知识库）或 `AI_SERVICE_PORT`（网关）改成其他端口
   （如 `8102` / `8100`），重新启动即可避开冲突。
   注意：若 Java 侧 `aicontent` 转发地址写死原端口，需同步修改，否则联调会断。
